# 《尸潮：最后一夜》测试与验收

**LAST NIGHT SURVIVOR**

本文用于网页与微信小程序的竖屏 2D 僵尸肉鸽生存原型。任何结果只能记录为 `PASS`、`FAIL`、`BLOCKED` 或 `NOT RUN`；计划执行、静态检查或旧版本结果不能代替当前版本实测。


## 3. 命名与迁移清单

- [ ] 游戏中文名只显示《尸潮：最后一夜》。
- [ ] 英文副标只显示 `LAST NIGHT SURVIVOR`。
- [ ] 玩家单位统一称“幸存者”。
- [ ] 敌对单位统一称“感染者”。
- [ ] 7 槽统一为：突击步枪、求生本能、3 个核心战术技能、2 个生存增益。
- [ ] 普通界面、管理员面板、日志和状态快照不残留旧西游角色/法宝术语。
- [ ] 旧资源或迁移说明如仍保留，不会在正式测试入口误导玩家。

## 4. 网页冒烟清单

- [ ] 页面可加载，无阻断性控制台错误。
- [ ] 画面保持竖屏布局；390×844 视口下无横向滚动和关键控件溢出。
- [ ] `WASD`、方向键和触屏摇杆至少对应平台可用输入正常。
- [ ] 幸存者移动不穿越明确障碍或画面边界。
- [ ] 突击步枪自动找到感染者并射击，不需要连续点击普通攻击按钮。
- [ ] 射击准备、枪口反馈、命中和后坐至少能被观察到。
- [ ] 感染者追击、接触伤害、受击、死亡和新单位生成正常。
- [ ] 生命归零进入失败状态，重开后本局状态被重置。
- [ ] 暂停时幸存者、感染者、射击、伤害和升级进度均停止结算。

## 5. 网页道具球、房屋和七槽清单

- [ ] 共显示 7 个槽位：当前枪械、求生本能、3 个核心战术技能、2 个生存增益。
- [ ] 开局仅普通突击步枪与求生本能，成长槽为空。
- [ ] 场景补给、击杀随机掉落可以接触拾取；道具不生成在建筑内或墙后无法取得的位置。
- [ ] 首次拾取获得 1 级道具；同类重复拾取提升等级与实际效果。
- [ ] 每类空槽容量生效，已满类别不能新增该类道具。
- [ ] 单个核心战术技能不会超过 5 级。
- [ ] 生存增益遵循各自有限等级，不默认套用核心战术技能上限。
- [ ] 满级重复或类别满槽道具产生替代奖励与明确反馈。
- [ ] 道具球有数量上限，经验升级不再弹窗，移动、射击、倒计时持续推进。
- [ ] 同类低品质球不会降低已有品质，高品质实际提高效果。
- [ ] 室外品质仅普通、精良；房屋搜索品质为精良、稀有、史诗。
- [ ] 靠近入口可按 E 或屏幕按钮进入，室内可移动并搜索，出口可回到原门口。
- [ ] 搜索点每局一次，反复进出不会刷新；室内外物件状态隔离并保留。
- [ ] 可拾取不同枪械，换装后名字、品质、伤害、射速、弹丸表现按武器变化。
- [ ] 房屋探索倒计时继续，感染者可以进入；暂停和结算后不能拾取或搜索。
- [ ] 重开清空技能、品质、枪械及所有房屋搜索状态。
- [ ] 至少一个核心战术技能升级后能看出伤害、范围、数量、频率或效果变化。

## 6. 固定能力清单

### 突击步枪

- [ ] 自动锁定射程内有效感染者。
- [ ] 当前目标死亡或离开射程后能重新锁定。
- [ ] 射速、伤害、弹道与表现节奏稳定，无单帧重复结算。
- [ ] 枪口、弹道/曳光、命中反馈不会被 UI 或大量特效完全遮挡。
- [ ] 暂停和结算期间不继续射击；拾取升级期间自动射击继续。

### 求生本能

- [ ] 触发条件与设计一致，可通过受伤或管理员手段稳定复现。
- [ ] 触发时有明确视觉/UI 反馈。
- [ ] 持续时间结束后状态正确恢复。
- [ ] 冷却有效，不会每帧重复触发或刷日志。
- [ ] 死亡、重开后不会残留上一局状态。

## 7. 感染者、特效与性能清单

- [ ] 普通感染者可从轮廓和颜色上与幸存者区分。
- [ ] 不同感染者类型具有可辨识的速度、耐久或攻击行为。
- [ ] 感染者不会直接生成在幸存者碰撞体内。
- [ ] 感染者数量会随时间或压力档位增加，并受明确上限约束。
- [ ] 常规目标 40 个同时存活感染者时记录实际体验，不预填“通过”。
- [ ] 管理员高压目标 60 个以上时记录 FPS/帧耗时、触控延迟和异常；达不到时记录真实上限。
- [ ] 战术技能命中、范围和控制状态可读，不被大量粒子完全遮挡。
- [ ] 特效增加后无持续增长的对象、计时器或内存迹象。
- [ ] 长时间战斗后摇杆、暂停、房屋交互仍及时响应。
- [ ] 浏览器控制台或小程序调试器无持续刷新的异常日志。

建议每个压力档至少观察 3 分钟，并记录感染者峰值、最低可感知帧率、设备温度异常和是否发生卡死。

- [ ] 无敌开关。
- [ ] 射程、攻击区域与碰撞判定层。
- [ ] 强制触发升级。
- [ ] 重开并清理本局临时状态。
- [ ] tick、生命、等级/经验、感染者数、目标、生成队列和本局 ID 等状态可读。
- [ ] 状态快照和事件日志可复制或截图回传。
- [ ] 关闭管理员模式后，普通玩家默认参数未被永久修改。

## 11. 三测试员分工

### 测试员 1：玩法与构筑

- 连续完成至少两局，使用不同的 3 核心战术技能 + 2 生存增益组合。
- 重点检查固定槽、锁定后的升级池、满级边界、死亡和重开。
- 回传 7 槽快照、最高等级、失败原因和最难理解的选择。

### 测试员 2：移动端 UI

- 优先使用真实手机，检查摇杆、安全区、按钮可达性和文字可读性。
- 重点观察大量感染者/特效时的触控延迟和界面噪音。
- 回传设备、系统、屏幕尺寸、截图和误触位置。

### 测试员 3：压力与管理员

- 使用管理员入口测试暂停、单步、生成感染者、无敌、判定层和强制升级。
- 分别记录低、中、高压力下的感染者数、帧率体感、错误和卡死情况。
- 回传状态快照、事件日志和最小复现步骤。

三份报告必须使用同一版本标识。测试员之间看不到彼此的实时战斗状态，这是当前预期，不是同步故障。

## 14. 测试结束条件

可提交合并的最低条件：

- 本次改动对应的清单已实际执行，所有阻断缺陷已修复或明确接受。
- 网页和小程序受影响规则已同步，或差异有明确负责人和后续项。

- 临时证据、缓存和账号信息未进入 Git；需要保留的正式证据可追溯到版本。
- 集成人根据真实结果更新 `STATUS.md`。
